# Phase 4 local history design
Use existing foundation tokens/layout/native inputs; no new branding. Place a separate local history section below workspace. Unsaved computation offers explicit checkbox disclosure and Save button. Disclosure names raw CSV snapshots, question, approved contract, results/report and source code, local-script accessibility, no encryption, quota/eviction. No new database is created at mount; previously consented history may be read.
Existing history inventory can list saved metadata after reload; no raw data restored until Load playback. Each entry shows ID, source hashes, saved size/origin, status/provenance. Load is explicitly old-report playback; Replay recomputes with live status/cancel and exact saved/current table differences, plus inspectable lineage/source. Original remains unchanged. Export downloads ZIP on click. Import input parses to in-memory preview; checkbox and confirmation persist atomically. Delete removes orphan snapshots transactionally. Fresh AI action restores approved snapshots to memory, remounts investigation with parent context and empty key/unchecked provider consent. Scrolling tables/code is local; labels/live regions/focus respect foundation conventions. Narrow viewport behavior is tested only; mobile hardware support remains deferred.
Design acceptance: implementation must preserve existing interface, exact numbers/status/provenance and no mount side effects. Independent design review at completion.

Flow/state contract: empty history says no saved records and never creates storage. Inventory/loading disables record actions. Save/import pending disables duplicate clicks; committed status appears only after transaction completion. QUOTA_EXCEEDED offers deletion/export and retry; STORAGE_UNAVAILABLE offers retry without reporting Save success; MISSING_INPUT explains deletion/eviction and exact re-import; corruption/version/compiler/runtime refusal shows the stable error and offers compatible original app/runtime rather than a silent migration. Replay states: RUNNING, MATCH, MISMATCH, INCOMPATIBLE_RUNTIME, MISSING_INPUT, UNSUPPORTED_OPERATION, EXECUTION_FAILED, CANCELLED. Cancellation leaves original visible and Retry starts a new record. Playback says stored historical CLIENT_REPORTED values, with imported origin separately indicated; only new recomputation gets a current local verification label.

Wireframe: one wide section [Save disclosure / Save] followed by [Saved list: ID, approximate bytes, origin / Load / Delete], selected record [Playback / manifest details / Replay / Cancel / Export / Fresh AI], replay comparison table [job, saved SQL/Pandas, new SQL/Pandas, match, status, provenance], import [file / validation preview / persistence checkbox / Confirm]. Tables/code use labelled focusable overflow regions; page remains single column at narrow widths. Native focus stays with initiating control; aria-live reports completion/error; actionable validation errors are adjacent to the matching input. Checkboxes: 'I approve saving these snapshots and artifacts on this browser' and 'I approve storing this validated imported bundle locally'. Import checkbox resets on every file change. Fresh AI remounts empty credentials and unchecked provider consent. Controls disable while computation or storage mutation is active.

Fresh comparison: a linked new run shows parent ID and compares hypothesis IDs (same labels are ordinal alignment only, not semantic equivalence), approved contract identities/dependencies, structured findings and verification. Measured token totals and provider elapsed milliseconds come from actual completed attempts; unavailable values say unavailable, ambiguous dispatch/billing remains separate. Plan/report differences are structural, never stochastic reproducibility claims. Original evidence/run remains read-only; Save new run is separately explicit.
