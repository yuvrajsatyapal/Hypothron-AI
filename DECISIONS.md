# Hypothron AI — Initial Architectural Decision Records

Date: 2026-10-10. Status “Accepted for planning” means a coherent documentation baseline, not completed implementation or proven feasibility. Reopen decisions when the listed validation gate fails. New records must include context, decision, alternatives, consequences and validation evidence.

## ADR-001 — Browser data plane, server control plane

**Status:** Accepted for planning. **Context:** Free-first operation and dataset privacy conflict with server-centric analytical execution. **Decision:** Next.js manages local bytes; FastAPI/LangGraph orchestrate approved metadata and analytical plans; DuckDB-WASM/Pyodide execute in browser memory. PostgreSQL is metadata-only. **Alternatives:** Server uploads/warehouse computation; browser-only LLM orchestration. **Consequences:** Limited device capacity, backend cannot prove local computations, internet required for new inference. **Validation:** Phase 1 network/storage and resource probes.

## ADR-002 — LangGraph roles inside one FastAPI service

**Status:** Accepted for planning. **Context:** Need real delegation, evidence-driven routing and durable continuation without distributed-service costs. **Decision:** Distinct planner, SQL analyst, optional Python analyst and report roles with typed contracts/tools; supervisor uses deterministic budgets and conditional routing. Profiling and verification are software tools, not compulsory LLM agents. **Alternatives:** Single prompt; separate agent microservices; mandatory fixed agent chain. **Consequences:** Stateful workflow complexity needs recovery testing and single-agent baseline evaluation. **Validation:** Phase 2 conditional/follow-up/interrupt fixtures and Phase 5 measured comparison.

## ADR-003 — Allowlisted operation IR for public execution

**Status:** Accepted for planning. **Context:** Python/SQL can invoke dangerous capabilities even in workers. **Decision:** Structured IR compiles through trusted implementations to SQL/Python templates; no unrestricted model-authored source execution. Display compiled source so the demo remains inspectable. **Alternatives:** AST denylist, fetch monkey-patching, arbitrary Pyodide source, paid server sandbox. **Consequences:** Unsupported analysis is explicit; agent generation is constrained. **Validation:** Phase 1 compiler and browser egress negative tests. Optional arbitrary code belongs to advanced local mode.

## ADR-004 — Separate numerical status from provenance

**Status:** Accepted for planning. **Context:** Two browser engines can agree while a client forges both results. **Decision:** Keep VERIFIED/DISPUTED/INCONCLUSIVE/NOT_CHECKED and a separate CLIENT_REPORTED/RECOMPUTED_LOCAL/RECOMPUTED_SERVER provenance. Public labels say locally verified. **Alternatives:** Trust hashes/job signatures; label all browser agreement server-verified; require dataset upload. **Consequences:** No remote attestation guarantee; trusted server verification deferred. **Validation:** Forged paired-result fixture must never receive server-attested provenance.

## ADR-005 — Metric contracts drive independent verification

**Status:** Accepted for planning. **Context:** LLM agreement does not validate math; correct math may use the wrong business meaning. **Decision:** Immutable metric definitions include joins/grain, units, filters, dates/timezones/nulls/rounding and tolerance. Separate SQL/Pandas evaluators recompute from original snapshot. **Alternatives:** LLM critic; replay analyst code as “independent” verification. **Consequences:** Common contract/compiler errors remain possible; golden/invariant tests are required. **Validation:** Phase 3 semantic mismatch, precision and join-cardinality fixtures.

## ADR-006 — Explicit local artifact save, transient backend state

**Status:** Accepted for planning. **Context:** Durability is needed for orchestration but local datasets must not be silently persisted. **Decision:** Memory by default, Dexie only on Save. PostgreSQL holds sanitized expiring checkpoints/metadata/approved aggregates with separate start consent. **Alternatives:** Automatic IndexedDB history; permanent cloud reports; no checkpoints. **Consequences:** Browser close loses unsaved bytes; server continuation may need exact reattachment; local storage can be evicted. **Validation:** Phase 1 no-save probes and Phase 4 atomic save/quota/deletion tests.

## ADR-007 — Versioned replay artifacts before agent integration

**Status:** Accepted for planning. **Context:** Reproducibility requires identity, runtime provenance and execution history from the beginning. **Decision:** Hash original bytes; version parse/metric/IR/compiler/runtime artifacts; execute saved operation DAG without inference and compare canonical typed results. AI re-investigation creates a new linked run. **Alternatives:** Store only reports; reprompt with original question; claim bitwise cross-runtime identity. **Consequences:** Runtime availability and floating-point variation limit replay. **Validation:** Phase 1 minimal replay, Phase 4 compatibility refusal and zero-provider-call tests.

## ADR-008 — Ephemeral request-scoped BYOK gateway

**Status:** Accepted for planning. **Context:** Provider CORS/capabilities vary; persistent keys enlarge breach impact. **Decision:** FastAPI fixed-provider adapters use credentials passed for authorized short execution segments; credentials stay outside checkpoints/artifacts. **Alternatives:** Encrypted key vault, browser direct providers, key in graph config. **Consequences:** Reload may require re-entry, ambiguous requests may incur charges, privacy requires minimized context. **Validation:** Canary redaction and provider error/retry tests.

## ADR-009 — PostgreSQL ledger, SSE downlink, POST results

**Status:** Adopted locally in Phase 2; hosted behavior remains unvalidated. **Context:** Browser jobs outlive API requests; free hosts can sleep/restart. **Decision:** Checkpoint pending jobs, interrupt LangGraph, SSE for observation, authenticated POST for idempotent results, fenced PostgreSQL run ownership. Short request-triggered segments, no durable in-process background task assumption. **Alternatives:** WebSocket-only state, polling as sole protocol, Redis/Celery. **Consequences:** Reconnect/reconcile logic; exact-once provider billing unavailable. **Validation:** Phase 2 crash-at-each-boundary tests. Polling remains a fallback for observation if SSE unsupported.

## ADR-010 — Free-compatible modular deployment

**Status:** Provisional candidates. **Context:** Need a publicly demonstrable bounded product without paid infrastructure guarantees. **Decision:** Candidate Vercel personal frontend/static executor, Render FastAPI and Neon PostgreSQL, with local fallback. No queue/vector SaaS. **Alternatives:** Paid containers/background workers, always-on cloud stack. **Consequences:** Cold starts, quotas, provider eligibility and global concurrency limits; no SLA. **Validation:** Phase 5 current terms and live-host probes; reopen if headers/assets/Python constraints fail.

## ADR-011 — Python persistence ownership and demo identity

**Status:** Accepted for planning; cross-site transport probe pending. **Context:** Project is Python/FastAPI despite generic toolkit Kotlin/Prisma defaults. **Decision:** SQLAlchemy async + Alembic + PostgreSQL integrity constraints; opaque expiring demo capabilities scope all records. Accounts/workspaces later. **Alternatives:** Two ORMs/migration authorities; unauthenticated public run IDs; premature enterprise auth. **Consequences:** Anonymous users need global abuse controls; cross-origin session/SSE handling requires tests. **Validation:** Ownership/expiry/CSRF fixtures and deployment cookie behavior.

## ADR-013 — Dataset-free bootstrap and network-denied compute

**Status:** Adopted in Phase 1; local Chrome probes pass, broader targets pending. **Context:** A compute-worker `connect-src 'self'` policy let a canary reach the static host despite a 404 response. **Decision:** Bundle/hash-check trusted runtime JavaScript during build. Load/hash-check a fixed binary/package manifest in the credential-free host before CONNECTED. Transfer immutable buffers to compute; provide memory-only asset readers while compute and nested-worker response CSP deny connections and arbitrary script imports. The main worker may create the fixed DuckDB child; the child may create no worker. **Alternatives:** Dataset-bearing network-enabled bootstrap, 404/POST-only filtering, monkey-patching fetch alone, removing independent Python. **Consequences:** Greater startup/memory cost; no new runtime/package downloads during computation; separate static headers/build packaging are mandatory. The host remains trusted static code and can fetch fixed assets; it is not a general code sandbox. **Validation:** Actual native XHR/fetch/script-import negatives plus genuine SQL/Pandas computation; child-worker native XHR and wrong-source probes now pass; device/deployment matrix remains open. Do not generalize local results to deployed origins.

## ADR-014 — Foundation capability transport

**Status:** Adopted locally; deployment transport unvalidated. **Decision:** FastAPI returns a random 256-bit demo bearer capability once; PostgreSQL holds SHA-256 only. The initial session expires 24 hours after creation, with no renewal endpoint yet. Expired reads are denied and creation lazily purges expired rows. The intended inactivity renewal/run-retention behavior remains Phase 2/5 work. **Alternatives:** URL tokens, user-selected owners, premature accounts, cross-site cookies before deployment probes. **Consequences:** Browser investigation integration must keep the token in memory, never persistent storage. CORS is not ownership; every future job route must enforce capability ownership. **Validation:** Real PostgreSQL tests for hash storage, unauthorized lookup and expiry/purge. Current tests are not proof of future job fencing, anonymous rate limits or live-host retention.

## ADR-015 — Initial validated desktop target and bounded CSV support

**Status:** Adopted for the local Phase 1 target on 2026-10-12 under the continuation brief's explicit device-scoping instruction. Public/mobile support remains deferred. **Context:** Fresh Chrome runs have substantial fixed WASM/package overhead. Desktop viewport emulation cannot validate phone CPUs/memory/CSP. No physical-device tooling is available (`xcrun devicectl` unavailable); the measured machine has 8 GiB RAM. **Decision:** Initial validated configuration is Chrome 154.0.8037.99 on macOS arm64, 8 GiB RAM, local fixed origins, pinned runtime manifest. Cap at 100,000 data rows, 10 MiB source, 128 columns and the existing conservative 128 MiB expansion estimate; quoted delimiters/newlines may cause early rejection. Report tracked-data allocations separately from whole-browser sampled RSS. Keep 30-second host/35-second client deadlines and one active job. Release job runtime buffers after initialization. **Alternatives:** Claim mobile support from a viewport; leave a million-row nominal ceiling unsupported by measurement; move raw bytes to server compute; discard independent Python. **Consequences:** This explicitly narrows initial support instead of silently waiving the roadmap. Other devices/browsers and arbitrary shapes near limits are unvalidated. These are accepted-operation ceilings, not a universal memory/latency guarantee. OOM may still terminate a tab; browser JS/WASM has no portable hard per-job heap quota. **Evidence:** Five-row and 100,000-row real-engine runs; new 100,000-row/64-padding run (~9.2 MB) gives 7,577 ms startup-to-evidence, 5,333 ms computation, 16,400,072 dataframe bytes, 11,376,640 tracked DuckDB bytes and 1,111,834,624 sampled process-tree RSS bytes. Both exact totals are 101000000 cents. The unpadded post-cleanup observation is 6,603 ms startup, 4,591 ms computation and 1,017,954,304 sampled RSS bytes. Samples are observations, not a statistically controlled optimization result. **Validation:** New row-ceiling regression failed before enforcement, then passed; rerun browser/build/type/integration gates and deep-dive/diagram checks before closing T1.5. Phase 5 must independently test its actual release targets and deployment.

## ADR-016 — Recoverable creation and fenced checkpoint/ledger reconciliation

**Status:** Adopted locally in Phase 2 on 2026-10-12. **Context:** Native checkpoints and business ledgers do not share one commit; lost initial ACKs must not trigger another billed run. **Decision:** Client UUID identifies an owner/input-scoped idempotent metadata creation. Creation performs zero inference; separate authorized advance supplies BYOK. Per-run row locks and lease holder/epoch/expiry fence native saver reads/writes; terminal work is immutable except identical accepted-result ACKs. Strict completed role replies cache by run/ordinal/context digest; RESERVED without reply exposes BILLING_UNKNOWN, never automatic retry. Issuance UUID is checkpointed before interruption and reconciled into the ledger; accepted results reconcile on fresh resume. Completed-state reads authenticate owner/expiry without an execution lease or provider call. Browser operation generations prevent old cancellation callbacks changing a newer run/key. **Alternatives:** Infer before returning an unrecoverable ID; pretend checkpoint/business commits are atomic; persist keys for background work; retry uncertain requests; add a queue. **Consequences:** 60s whole-segment deadline, separately bounded5s cleanup,90s lease,5s DB limits,2 process-local segment slots,65s browser API deadline and10min interaction ceiling. These do not establish deployment-global quotas or exactly-once billing. Expiry denies access immediately; bounded lazy sweep removes native payloads before business cascades. Scheduled purge/backups and hosted admission remain Phase5. **Evidence:** Real PostgreSQL crash/idempotency/fencing/expiry tests, zero-inference creation/lost-ACK tests and realChrome conditional investigation/privacy/cancellation fixtures. See Phase2 report/deep dive for exact final counts. No live-provider/model or hosted guarantee is inferred.

## ADR-017 — Versioned exact verification and approved derived joins

2026-10-12 accepted for Phase 3. Preserve revenue_sum v1 wire/source semantics. Version 2 adds declared unique grain, explicit fixed-offset timestamps, USD/EUR minor scale two and JPY scale zero, and an optional bounded left join against a second hash-bound local snapshot. Independent SQL and Pandas validate original grains, lookup uniqueness, primary relationship cardinality, unmatched keys and joined populations before aggregating. Both sources remain in browser memory and a relationship requires explicit approval. Derived joined tables are ephemeral, never replacements of source bytes. No arbitrary SQL, many-to-many join, FX conversion or named-zone/DST inference is introduced. Unsupported semantics refuse execution.

Paired bounded diagnostic counts include the exact contract; backend comparison records canonical ASCII/sorted-JSON SHA256 contract identity, exact tolerance, original/lookup hashes via contract and predecessor evidence IDs. Incompatible semantics are INCONCLUSIVE; invariant/numerical contradictions are DISPUTED. Correction reruns original approved snapshots/semantics at most twice per contract within the six-job cap, without inference. No automatic semantic revision; user may start a separately approved new run. Native graph checkpoints and business ledgers use the existing fenced recovery protocol. JSONB carries versioned contracts/diagnostics, so no new table or migration is required. CLIENT_REPORTED remains untrusted client provenance.

## ADR-018 — Evidence-grounded reports and deterministic publication

2026-10-12 accepted for Phase3. Provider reporting proposes bounded typed total/count/percentage-change claims, each bound to explicit evidence IDs, source/contract identity and units. Python Fraction validates exact mathematics; percentage-change operands are ordered baseline/current, have compatible currency/version/business semantics, and a nonzero baseline. Browser BigInt independently validates the same relationship. Integer claims normalize to integer strings before monetary rendering. Nonterminating fractions with no exact bounded decimal proposal are not rounded into proof.

Citation existence is necessary but insufficient. Orphan/incompatible/unverified operands, unsupported numbers and causal/correlation/contribution relations fail validation. The supported operations compute revenue totals, not statistical association, decomposition or causal identification. Arbitrary narrative, including obfuscated/spelled-out figures, is refused publication through a small qualitative grammar. Published conclusions/findings/charts are deterministic from accepted evidence; invalid drafts or exhausted report inference budgets fall back without another provider call. This deliberately trades prose flexibility for numerical authority. React renders text and typed SVG, with exact accessible tables and explicit status/provenance.

Old Phase2 checkpoint evidence is enriched from its original issued jobs before report generation without overwriting accepted business results. Completed legacy free-text reports are withheld from numerical presentation and marked for evidence revalidation. Original contracts/worker source/runtime and checkpoint fencing remain authoritative; this is presentation/contract expansion, not new backend analytics or trusted server execution. JSONB versioned report payloads need no migration.

## ADR-019 — Explicit local artifacts, immutable manifests and stored ZIP

Accepted 2026-10-12 for Phase4 local desktop implementation. Application memory remains default. Dexie4.2.1 database `hypothron-local-v1` opens/creates only after Save or confirmed Import; inventory of existing databases permits reading already-consented metadata after reload. Snapshots keyed by SHA256 are immutable; investigation IDs cannot overwrite a different manifest digest. One IndexedDB read-write transaction commits manifest and snapshot references, evaluates logical quota and deletes last-reference blobs. Crypto/CSV validation occurs before transactions to avoid premature commits. Eviction, browser quota, crashes and storage denial remain possible; no durable-storage or encryption guarantee.

Manifest schema1 uses sorted-key compact ECMAScript JSON, finite numbers, exact Unicode scalars without normalization, ordered dependency/evidence arrays and sorted snapshot descriptors. SHA256 identifies canonical bytes, not author trust or execution attestation. Version1 supports csv-utf8-v1/exact-minor-units-v1, revenue_sum IR1/2, the existing fixed compiler and runtime asset lock. Unknown manifest/storage/parser/tolerance versions refuse; no automatic migration. Explicit future migration must create a new labelled artifact and preserve original history.

Portable archives use strict uncompressed ZIP(STORED), manifest.json and snapshots/<lowercaseSHA256>.csv only. No arbitrary archive instructions or imported source execution. Compression/encryption/ZIP64/descriptors/extra fields and unsafe/duplicate/unknown paths refuse. This narrow format avoids decompression bombs and third-party decompression allocation. Alternative permissive compressed ZIP improves size but broadens parser/expansion risk; cloud sync/encryption require separate design, not implicit Phase4 work.

## ADR-020 — Immutable captured runs and separate fresh investigation

**Status:** Adopted locally in Phase4. **Context:** Persisting only a primary local calculation loses multi-job accepted evidence and unused approved datasets; a new model invocation cannot be called deterministic replay. **Decision:** Retain local compiled results before result submission, capture only durable accepted IDs at completion, freeze creation question/provider/model across Resume, retain approved unused inputs, and link fresh runs through a distinct ID/parent. Fresh preparation is memory-only with empty key and unchecked provider consent; Start follows existing API/provider budgets. Owned ledger observations supply measured tokens and request time; unknown remains null. **Alternatives:** Reconstruct local execution from server scalars, silently resume saved capabilities, reprompt on replay, or overwrite the original. **Consequences:** Larger explicit snapshots and structural comparisons; no reasoning reproducibility or price inference. Lost-ACK recovery remains replayable. Final manifest v1 includes approved contracts and supersedes unsupported unreleased task-development v1 artifacts without migration; Phases1–3 had no persistent format. Future migration must be explicit and preserve original history. **Validation:** fresh-history/recovery browser fixtures, owner/unknown measurement tests, immutable parent and active inference refusal.

The Phase4 executor bootstrap sends credential-free PROBE/HOST_READY messages, validates exact parent/frame origin and source, then transfers one channel. Iframe load re-probes only a pending bootstrap, preserving accepted channels. Upload is disabled until hydration; a delayed-document browser test and negative source/origin unit test protect this startup boundary. No CSP or execution permissions changed.

## ADR-021 — Isolated CI validation target and inference refusal

2026-10-12 accepted for Phase4.5. Read-only GitHub Actions on Ubuntu24.04 (x64 fast gates / arm64 browser gate) uses frozen locks, pinned tool/actions/PostgreSQL and committed runtime hashes. Three independent static/backend/frontend gates precede real browser integration with its own disposable database and test-only mocked HTTP API. CI selects lockfile Chromium, distinct from ADR015 macOS Chrome154 product acceptance. Tests refuse accidental non-loopback Python sockets with caught-violation audit and browser provider requests with an independent request audit; worker CSP remains separately tested. These controls are not a hostile-code/native-extension OS sandbox. No provider keys, production DB, secret-bearing artifacts or deployment authority. Native saver schema is migration-owned, so validate up/down/up plus scoped head/table/column/nullability inspection rather than unfiltered autogeneration that proposes deleting saver tables. Alternatives: macOS-only CI, mutable installed Chrome, server reuse, absent-key-only guards, generated runtime cache/artifacts. Runner evidence: local x64 emulation passed fast gates/direct engines but exceeded the unchanged35s UI deadline; the browser job uses standard native ubuntu-24.04-arm, verified available for public/private repositories, with full native Linux validation separately recorded. No test/deadline relaxation. Trade-off: two independently verified bootstraps and production builds across isolated frontend/browser jobs; one expensive browser installation. Hosted execution remains unverified until separately authorized push. Phase5 remains unstarted. See docs/CI_CD.md and Phase4.5 report.

## ADR-022 — Parquet canonical snapshots and versioned source lineage

Accepted for Phase5 local scope. Decode bounded Parquet with the existing pinned DuckDB-WASM on the credential-free executor origin. Inspect footer/metadata row counts and uncompressed estimates before materializing scalar supported columns. Integers, exact decimals, booleans and UTF8 strings serialize deterministically to canonical CSV; floating, binary, nested, dates and timestamps refuse instead of inventing precision/timezone semantics. Timestamp strings remain subject to approved IR validation. Empty strings/control characters refuse to avoid CSV missing-value ambiguity. Original source bytes and SHA256 remain immutable alongside a derived CSV SHA256 and `parquet-csv-v1` normalization identity. The user approves this derived version. This is shared Parquet decoding followed by genuinely independent DuckDB/Pandas arithmetic, not independent parsing.

Manifest2 adds strict source-lineage records and original Parquet descriptors. CSV-only artifacts remain manifest1 with unchanged fields and archive paths. Version2 archives add only hash-named `.parquet` original snapshots; unknown versions/paths/lineage refuse, with no implicit migration. Replay verifies both byte identities and recomputes the saved canonical CSV without inference or re-decoding; hashes do not attest a historical conversion or adversarial client honesty. Original plus derived blobs count toward the existing30MiB artifact/run bound; max three analytical source datasets includes lookups, with at most three additional original blobs. The logical64MiB storage quota is unchanged.

Conversion keeps10MiB original and10MiB derived caps,100000rows,128columns, conservative128MiB decoded estimate and existing30s/35s termination. The preexisting10MiB combined primary+lookup canonical CSV limit per calculation also remains; three investigation sources do not expand it. Metadata itself requires decoding and hostile allocation may precede estimates: these bounds are not hard heap isolation. No added parser dependencies, raw upload, new backend operation or public deployment claim.
